# 医械法规标准导航 · SKILL

本技能是 **MedXpert-RA-Knowledge 标准知识库**的导航与编排层。底层查询由 `medxpert-ortho-mcp` 提供（标准能力已作为其 module 合并进这唯一共享 MCP），本技能负责**正确地问、正确地答**。

> 知识库是会自我进化的活系统（双时态 + 自进化协议）。本技能只调用、只标记，**绝不自动改写活库**。

---

## 一、何时用

- 用户问某条标准/法规的**现行状态、代号、适用范围**
- 需要按**业务日期**判定该日适用哪版法规（如 GMP 2014 vs 2025）
- 需要**分类判定树 / 注册路径 / 临床要求 / 发补风险 / 周期费用**等判定引擎结论
- 发现知识库缺口、待核实项，需要**标记**进队列

不适用：纯临床试验方案设计、药品注册、单纯商业渠道招标。

---

## 二、MCP 工具（medxpert-ortho-mcp · 标准 module）

| 工具 | 用途 |
|---|---|
| `list_standards(keyword, cat)` | 查检测标准索引（单一事实源） |
| `query_standard(code/keyword)` | 查单条标准 + 关联 KB 法规原文 |
| `find_judgment_tree(product_type, country)` | 找判定引擎文档（分类/路径/临床…） |
| `get_region_path(country)` | 按国别返回注册路径选择器 + 结构化解读 |
| `check_timeline(business_date)` | 按业务日期判定有效法规 + 切换预警 |
| `report_gap(issue, source, severity)` | **仅标记**缺口到 MCP-标记队列（不改写活库） |
| `evolve_status()` | 健康度体检（字段完整率/时效） |
| `reindex()` | KB 被手动编辑后重建索引 |

> 若 `medxpert-ortho-mcp` 未配置，提示用户先在 MCP 配置中加入该服务并设 `KB_ROOT` 指向知识库目录（标准能力已作为其 module 合并其中）。

---

## 三、强制前置：版本判定（每次答法规题必做）

1. 确定**业务日期**（用户未指定 = 今天）
2. 调 `check_timeline(business_date)` → 取 `valid_from ≤ 业务日期 ≤ valid_to` 的条目
3. 若返回 `switchWarnings`（距切换点 ≤90 天）→ **必须同时提示新旧两版 + 切换日期**
4. 只采用现行有效版本作为结论依据；过期内容（`status: 已过时`）不作为结论

---

## 四、来源等级话术（不可违反）

| source_tier | 可否直接给客户结论 | 话术 |
|---|---|---|
| 官方原文 | ✅ 可 | 标文号 + 施行日 |
| 官方解读 | ✅ 可，标注"解读" | "根据官方解读……" |
| 行业整理 | ⚠️ 需提示 | "行业通行做法，建议与主管当局确认" |
| 自建推导 | ❌ 不可直接给 | "我们的判断是……仅供内部参考，需核实" |

判定引擎文档（`03-判定引擎/`）多为 `行业整理/自建推导`、`confidence: low`，引用须声明，且**案例库当前 0 条真实实录**，不得暗示有实证。

---

## 五、红线（不可违反）

1. 🚫 **禁止自动改库** —— 发现过时/冲突/缺口，只调 `report_gap` 标记，不删不改
2. 🚫 **不确定的不答** —— 库里无相关信息明确说"未找到"，禁止编造
3. 🚫 **自建推导不冒充官方** —— 必须标 source_tier + confidence
4. 🚫 **案例信息不得反推** —— 脱敏占位（[公司A]/张三）不得展开
5. 🚫 **不构成合规意见** —— 最终以官方现行版 + 有资质机构意见为准

---

## 六、典型流程

```
用户问标准/法规
  → check_timeline(业务日期) 定版本（双版本提示若临近切换）
  → query_standard / list_standards 取现行状态
  → 分类/路径类 → find_judgment_tree / get_region_path
  → 按来源等级给话术；缺口 → report_gap 标记
```
